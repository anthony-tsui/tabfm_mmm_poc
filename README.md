# TabFM vs Meridian MMM — synthetic comparison PoC

Side-by-side evaluation of **Google Research TabFM** (tabular foundation model)
and a **Google Meridian / Meridian-style MMM baseline** on the **same**
Meridian-shaped weekly marketing-mix dataset.

> **Synthetic / dummy data only.** Every KPI, spend, impression, and planted
> `contribution_*` value in this repository is simulated. Nothing here is an
> estimate of real campaign performance. Do not use these numbers for budgeting
> or business decisions.

## What this PoC measures

On a fixed train/test **time split** (earlier weeks = context/train, later weeks
= holdout):

| Metric family | Description |
| --- | --- |
| Holdout KPI | RMSE, MAE, R², MAPE of predicted revenue vs holdout weeks |
| Contribution recovery | If `contribution_*` columns exist: MAE / correlation of channel contribution shares vs planted ground truth |

**Framing hypothesis:** treat MMM predictive evaluation as tabular regression —
features = media spend/impressions (+ controls); target = KPI (revenue). TabFM
uses in-context learning over the train rows; the MMM baseline is fit on the
same train period and scored on the same holdout.

## Models

### TabFM

- Source: [google-research/tabfm](https://github.com/google-research/tabfm)
- API: `TabFMRegressor` with PyTorch backend (`tabfm_v1_0_0_pytorch`)
- Pretrained weights auto-download from Hugging Face
  (`google/tabfm-1.0.0-pytorch`)

**Weight license:** TabFM *source* is Apache-2.0; default pretrained weights use
the separate **`tabfm-non-commercial-v1.0`** license (non-commercial /
non-production). Commercial use of those weights is not permitted. See the
upstream README.

If Hugging Face download or GPU/CPU weight load fails, use `--dry-run` (Ridge
mock) so the metrics table and notebook still run end-to-end.

Optional: set `HF_TOKEN` if the Hub requires authentication for the weight
repo. Do not commit tokens.

### Meridian baseline

- Prefer real [Google Meridian](https://developers.google.com/meridian)
  (`pip install google-meridian`) with **minimal** MCMC settings when
  installable.
- If Meridian is missing or too heavy on CPU, the PoC uses a documented
  **Meridian-style baseline**: geometric adstock + Hill saturation + Ridge,
  clearly labeled as a proxy (not full Bayesian Meridian).

## Quick start

```bash
# Core deps + TabFM clone (best effort)
bash scripts/install_deps.sh

# Optional full Meridian
INSTALL_MERIDIAN=1 bash scripts/install_deps.sh

# Always-works path (mock TabFM + Meridian-style proxy)
python scripts/run_comparison.py --dry-run

# Best-effort real TabFM (+ Meridian if installed)
python scripts/run_comparison.py -v

# Force proxy even if Meridian is installed
python scripts/run_comparison.py --no-meridian
```

Outputs land in `results/metrics.json` and `results/metrics.csv`.

Notebook: `tabfm_vs_meridian.ipynb` — prints the same side-by-side table and
repeats the synthetic-data disclaimer.

## Assumptions (documented choices)

1. National weekly grain; 8 train / 4 holdout weeks by default (`train_frac=2/3`).
2. TabFM contribution recovery uses leave-one-channel ablation on holdout
   predictions (approximate).
3. Meridian-style contributions use `coef × transformed media` on holdout.
4. Full Meridian, when used, runs tiny chains suitable only for PoC smoke tests.
